# CDS GCDS

A standalone GC Articles theme using GC Design System components instead of
WET/GCWeb. There is no parent-theme dependency on `cds-default`.

## Installation

Deploy this directory with the GC Articles WordPress application, its Composer
dependencies and the `cds-base` plugin. Activate **CDS GCDS** under Appearance >
Themes. The theme uses the application's existing site settings and menu locations.
It is not a generic theme for an otherwise empty WordPress installation.

The theme requires the application's supported PHP/WordPress versions and PHP's
DOM extension. GCDS components **1.7.1** and CSS Shortcuts **1.2.0** load from
`cdn.design-system.canada.ca`. Allow this origin in your deployment's content
security policy. The Canada.ca topic menu also retrieves its bilingual menu from
`www.canada.ca`. No Node build is required to deploy the theme.

## Existing content and behaviour

Existing block names and saved WET HTML are **not rewritten**. Rendering converts
paragraphs, headings, links, button links, file download buttons, accordions,
expanders, alerts, screen-reader text, and image/media captions and quote citations
to GCDS components. This keeps existing content editable and permits switching back
to `cds-default` without migrating its saved data.

Columns, media/text layouts, galleries and latest-post grids become GCDS grids.
Groups become GCDS containers. Cover media and flex-based Row/Stack groups retain
their native WordPress layout inside a GCDS container so backgrounds, overlays and
flex behaviour survive.

GCDS has no component for images, video/audio/embeds, lists, quotes, code,
separators or spacers, so these keep native, semantic elements styled with GCDS
CSS Shortcuts and tokens: authored lists get `list-disc`/`list-circle`/
`list-decimal` (ordered-list marker types map to `list-lower-alpha` and similar),
images get `img-responsive`, quotes and code use spacing/background shortcuts,
separators use token borders, and spacers up to 100px map to the nearest
`pt-<token>` spacing (taller spacers keep their exact height). Lists generated by
other blocks (latest posts, galleries, menus) keep their own layout. WordPress
block CSS remains available, but WET assets and the legacy public block styles are
not loaded.

The GCDS page shell retains search parameter `s`, navigation locations `header`,
`topbar` and `footer`, page ancestry, breadcrumbs, categories,
authors, dates, featured images, document/archive pagination and maintenance mode.
The header does not display a built-in sign-in or sign-out button.
GitHub publish settings/webhooks and analytics tracking retain their existing option
names and validation. Comments remain hidden, matching the original theme.
Default government footer destinations are preserved in a contextual footer band;
GCDS also supplies its standard full-footer links.

The existing `show_wet_menu` setting still chooses custom navigation versus the
Canada.ca topic menu; its stored name is retained for compatibility. The FIP
destination retains the existing forced-HTTPS behaviour, including on HTTP-only
local sites.
GCDS navigation links have no `target` API. Menus containing new-window or named
targets therefore use GCDS links/details inside a native navigation landmark to
preserve those destinations and submenu behaviour. Other menus use GCDS top nav.

## New blocks

The **GC Design System** inserter category contains 17 server-rendered blocks:

| Content | Layout/navigation |
| --- | --- |
| Heading (h2-h6) | Container |
| Text | Grid |
| Link | Grid column |
| Button link | Pagination (previous/next) |
| Card | Side navigation |
| Details | Navigation group |
| Notice | Navigation link |
| Table | |
| Screenreader-only text | |
| Icon | |

Use the block inspector to configure component attributes. Text supports limited
rich formatting; link and card descriptions cannot contain nested links. A grid
accepts only grid columns, and navigation groups/links stay inside side navigation
or other groups. Invalid required fields, URLs or table JSON produce an explicit
editor warning or rendered danger notice and a PHP log entry.

New blocks store attributes and inner blocks, not raw custom-element HTML, so
WordPress HTML sanitization does not strip GCDS markup when saving. **New
`cds-gcds/*` blocks require this theme to render**; switching back only restores
rendering of the original blocks. The page title supplies h1: use h2-h6 for authored
headings and review existing heading outlines before deployment.
Place cards under an h2 section: GCDS card-title levels start at h3.

Scope deliberately excludes form-authoring blocks, event-driven alerts and form
progress/error helpers. Header, footer, branding, search, breadcrumbs, language
selection, topic/top navigation and date modified belong to templates rather than
duplicable content blocks. Table filter controls are runtime UI, not form blocks.

### Tables

The new Table block takes JSON arrays, for example:

```json
[{"field":"name","header":"Name"},{"field":"count","header":"Count"}]
```

```json
[{"name":"Example","count":2}]
```

Columns need unique fields and headers. Custom managed/slotted cell templates are
not accepted by this block. Sorting, filtering and pagination are optional.

Simple legacy tables convert to `gcds-table`. The `is-style-filterable` class enables
its filter, sort and pagination controls.

Rich cells, links, row headers, footer rows and merged cells retain a native table
inside a token-styled GCDS container instead of losing content or semantics.
Filterable rich tables with one header row, one body and no merged cells use GCDS
controls for text filtering, ascending/descending sorting and 10/25/50/all-row
pagination. Decimal numbers sort numerically; other values use locale-aware text
sorting. Captions remain accessible.

Merged tables, multiple bodies or incompatible headers show all rows and explicitly
explain why filtering/sorting is unavailable. Split these into rectangular tables
if interactive controls are required. No WET/DataTables code is loaded.

## English and French

The theme retains the `cds-snc` text domain, includes French PHP and editor
translations, and sets the document language so GCDS localizes its controls.
Keep using WPML or the existing `locale` and `locale_switch_link` page metadata.
The latter must contain JSON with a `url` pointing to the equivalent page in the
other language. A missing mapping is logged and does not invent a translation URL.
User-authored content and inherited homepage-pattern copy still need translation.

Regenerate catalogues after changing strings:

```sh
wp i18n make-pot wp-content/themes/cds-gcds wp-content/themes/cds-gcds/languages/cds-snc.pot --domain=cds-snc --exclude=tests
msgmerge --update --backup=none languages/fr_CA.po languages/cds-snc.pot
msgfmt --check -o languages/fr_CA.mo languages/fr_CA.po
wp i18n make-json wp-content/themes/cds-gcds/languages --no-purge
```

Run `wp` commands from the WordPress application root and `msgmerge`/`msgfmt` from
this theme directory.

## Validation

From the repository root, using the existing `wp-env` installation:

```sh
npx wp-env start
npx wp-env run tests-cli wp theme activate cds-gcds
npx wp-env run tests-cli wp plugin activate cds-base
npx wp-env run tests-cli wp eval 'require "wp-content/themes/cds-gcds/tests/rendering.php";'
npx wp-env run tests-cli wp eval 'require "wp-content/themes/cds-gcds/tests/fixtures.php";'
```

Rendering checks exercise real WordPress block rendering, sanitization, UTF-8,
legacy compatibility, table fallbacks, layout behaviour and pagination bounds.
Fixtures create/update only `cds-gcds-test-en` and `cds-gcds-test-fr` in a local
`localhost:8889` site using this theme. They are not intended for production.
The site counter's backend requires a multisite installation; the single-site
fixtures test its markup conversion, not the multisite count query.

For browser checks, install `playwright` in a scratch directory and run the following
from that directory (replace `/path/to/repository`):

```sh
npm install playwright
npx playwright install chromium
node /path/to/repository/wordpress/wp-content/themes/cds-gcds/tests/browser.mjs http://localhost:8889
```

This checks all 17 components, language destinations, details, rich-table
filtering/sorting/pagination and mobile layout in both languages. Also verify editor
save/reload, maintenance-page status, search submissions and any site-specific
menus/content before deployment. Run `php -l` on theme PHP and the repository's
WordPress JS linter on `js/blocks.js` and `js/tables.js`.

When available, use the GCDS skill's markup and browser/axe checkers on **rendered
pages**, not PHP fragments. PHP's `wp_head()` supplies the document title and
dynamic attribute concatenation can produce source-linter false positives.
GCDS 1.7.1's French pagination has a known upstream accessible-label mismatch;
do not patch its shadow DOM. Legacy `cds-base` blocks also retain their existing
WordPress API-version warnings; their saved block formats are intentionally unchanged.
